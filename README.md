# ФармКонтроль (Home Pharmacy)

Веб-приложение для управления **аптекой в сельских местах**: ведение учёта лекарств, болезней, симптомов, действующих веществ и остатков препаратов с контролем сроков годности.

Построено на **Spring Boot 3.5.5** (Java 17) с UI на **Thymeleaf + Bootstrap 5** и базой данных **PostgreSQL** (JPA / Hibernate).

---

## Функциональность

Приложение позволяет вести учёт по пяти связанным сущностям:

| Сущность | Что хранит |
|----------|-----------|
| **Лекарство** (`Medication`) | название, описание, фото, **цена**, признак «по рецепту», набор болезней и действующих веществ |
| **Болезнь** (`Disease`) | название, описание, связанные симптомы |
| **Симптом** (`Symptom`) | название |
| **Действующее вещество** (`ActiveIngredient`) | название, описание |
| **Поступление в аптеку** (`Pharmacy`) | привязка к лекарству, количество, розничная цена, дата покупки, срок годности |
| **Архив** (`Archive`) | списанные (просроченные) партии с розничной ценой и датой списания |
| **Пользователь** (`User`) | логин (телефон покупателя или имя сотрудника), пароль, роль |

### Связи между сущностями
- **Симптом ⇄ Болезнь** — многие-ко-многим (у болезни может быть много симптомов).
- **Болезнь ⇄ Лекарство** — многие-ко-многим (лекарство лечит несколько болезней).
- **Действующее вещество ⇄ Лекарство** — многие-ко-многим (у лекарства несколько действующих веществ).
- **Лекарство ⇄ Поступление** — один-ко-многим (у лекарства может быть несколько поступлений с разными сроками годности).

### Разделы и возможности

**💊 Лекарства (`/medication`)**
- Список лекарств с пагинацией и поиском по названию.
- Добавление / редактирование / удаление лекарства.
- Загрузка фотографии лекарства (сохраняется в каталог `uploads/`, по умолчанию `/no-photo.jpg`).
- Просмотр лекарств по конкретной болезни (`/medication/{id}/disease`).
- Просмотр лекарств по действующему веществу.

**🦠 Болезни (`/diseases`)**
- Список болезней с пагинацией и поиском по названию.
- Добавление / редактирование / удаление болезни с привязкой симптомов.
- Просмотр болезней по выбранному симптому (`/diseases/{id}/diseases`).

**🧪 Действующие вещества (`/ingredients`)**
- Список с пагинацией и поиском по названию.
- Добавление / редактирование / удаление вещества.
- Просмотр лекарств, содержащих конкретное вещество (`/ingredients/{id}/medications`).

**🤒 Симптомы (`/symptoms`)**
- Список с пагинацией и поиском по названию.
- Добавление / редактирование / удаление симптома.

**🏥 Поступления / Аптека (`/pharmacies`)**
- **Главная страница-обзор** с тремя блоками:
  - весь список поступлений (пагинация, поиск по названию лекарства, сортировка по полю);
  - **недавние поступления** (последние подтверждённые заказы покупателей);
  - **истекает срок годности** (срок ≤ 7 дней от сегодня).
- Детальная карточка поступления (`/pharmacies/detail/{id}`).
- Добавление / редактирование / удаление поступления (выбор лекарства, количество, розничная цена, даты).
- Отдельная страница **просроченных** препаратов (`/pharmacies/expired`) и кнопка **списания всех просроченных** (`/pharmacies/expired/write-off`) — списанные партии не удаляются навсегда, а переносятся в историю.
- **История поступлений / Архив** (`/pharmacies/archive`): единый журнал всех партий (активные в аптечке, списанные просроченные и удалённые вручную) с **поиском по названию лекарства** и **сортировкой по полю** (дата покупки / название / срок годности). Удаление партии переносит её в историю, а не стирает безвозвратно.
- Отдельная страница партий **с истекающим сроком** (`/pharmacies/expiring`).

### Роли пользователей и авторизация (Spring Security)

В приложении две роли, разграничение доступа настроено на уровне маршрутов:

| Роль | Доступ |
|------|--------|
| **Покупатель (гость)** | Каталог `/catalog` (просмотр лекарств, поиск по названию, по болезням/симптомам/веществам). **НЕ может** оформлять заказы/заявки и редактировать справочники. |
| **Покупатель (зарегистрированный)** (`ROLE_CUSTOMER`) | Всё, что и гость, плюс **оформление заказа** и **заявки**, история своих заказов `/my-orders` и заявок `/my-requests` со статусами и чат по заявке. |
| **Сотрудник** (`ROLE_EMPLOYEE`) | Управление лекарствами, болезнями, симптомами, веществами, поступлениями/аптечкой и архивом + панели заказов `/orders` и заявок `/requests`. Главная (логотип «ФармКонтроль») ведёт на аптечку `/pharmacies`. Кнопки «Заказать на выкуп»/«Заявка» в каталоге для сотрудника скрыты. |

- Регистрация покупателя — по адресу `/register` (имя, телефон в формате маски, пароль). Логин = номер телефона.
- Вход — по адресу `/login` (сотрудник: логин `admin`; покупатель: телефон и пароль). После входа пользователь перенаправляется в свой раздел в зависимости от роли.
- Все управляющие маршруты (`/medication`, `/diseases`, `/ingredients`, `/symptoms`, `/pharmacies`, `/orders`, `/requests`) доступны только сотруднику; каталог и статические ресурсы — всем.

### Каталог покупателя (`/catalog`)

- Список лекарств с **актуальной ценой** и **наличием** (остаток с учётом не истёкших сроков годности).
- Поиск по названию, а также просмотр по **болезни**, **симптому** и **действующему веществу**.
- Карточка лекарства: цена, наличие, лечение болезней, действующие вещества.
- **Заказ на выкуп** лекарства, которое есть в наличии (имя, телефон, количество). Нельзя заказать больше, чем есть на складе. **Оформление заказа и заявки доступно только зарегистрированному покупателю.**
- **Заявка** на лекарство, которого нет в наличии (название, количество, комментарий, имя, телефон).
- Зарегистрированный покупатель видит **историю своих заказов** (`/my-orders`) и **заявок** (`/my-requests`) с актуальными статусами.

### Рецептурные препараты

- При создании/редактировании лекарства есть переключатель **«Отпускается по рецепту»**.
- В каталоге и карточке такой препарат помечается бейджем **«По рецепту»**.
- При оформлении заказа на рецептурный препарат показывается предупреждение: «Препарат отпускается по рецепту. При получении предъявите рецепт от врача».

### Обработка заказов и заявок сотрудником

- Панель **заказов** `/orders`: все заказы покупателей со статусами **Новый / Подтверждён / Выкуплен / Отклонён**, подтверждение, отметка выкупа, отклонение, счётчик новых.
- Панель **заявок** `/requests`: заявки на отсутствующие лекарства, одобрение / отклонение, счётчик новых.
- **Чат по заявке**: при нажатии «Чат» на строке заявки (у аптекаря и у покупателя) открывается окошко в правом нижнем углу с историей переписки (покупатель ↔ аптекарь). Сообщение аптекаря помечает заявку непрочитанной, у покупателя появляется **значок** в меню «Мои заявки».
- Покупатель может **подтвердить** (готов предъявить рецепт) или **отменить** свою заявку; после этого у аптекаря остаются кнопки **одобрить/отклонить**.

### Валидация данных
- Названия сущностей обязательны и уникальны (проверка дубликатов с сообщением об ошибке).
- Лекарство требует выбора хотя бы одной болезни; болезнь — хотя бы одного симптома.
- **Цена лекарства** обязательна и неотрицательна.
- Количество должно быть > 0.
- Срок годности — не в прошлом (`@FutureOrPresent`), дата покупки — не в будущем (`@PastOrPresent`).
- **Розничная цена** поступления обязательна и больше 0.
- Поля заказа/заявки (имя, телефон, количество) обязательны.
- **Номер телефона** проверяется по маске (например, `8 900 123-45-67` или `+7 900 123-45-67`) в заказе, заявке и при регистрации покупателя.

## Запуск проекта

Требуется **Java 17** и **Docker** (для PostgreSQL).

### 1. Запустить базу данных (PostgreSQL)

Из корня проекта (`docker-compose.yml` поднимает БД на порту **5433**, БД `home_pharmacy`, логин/пароль `postgres/postgres`):

```bash
docker compose up -d
```

Проверить, что БД запустилась:

```bash
docker compose ps
```

> Если контейнер `home_pharmacy_db` создан в контексте Docker Desktop и не виден в обычном контексте, используйте:
> ```bash
> docker --context desktop-linux compose up -d
> ```

### 2. Запустить приложение

**Вариант A — командой (Maven wrapper):**

```bash
./mvnw spring-boot:run
```

**Вариант B — из IDE:** запустите класс `HomePharmacyApplication`.

### 3. Открыть приложение

- Адрес: **http://localhost:8080**
- Сотрудник: логин `admin`, пароль `admin123`
- Покупатель: регистрация через `/register` (логин = номер телефона)

> При первом старте на пустой БД приложение автоматически создаёт таблицы и заполняет демо-данными
> (`DemoDataInitializer`), а также учётную запись сотрудника `admin` (`DataInitializer`).
